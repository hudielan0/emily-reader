# Emily阅读 · 第一版技术实现方案

> 状态：初稿（2026-11-04）。依据 [产品设计](product-design.md)。
> 界面已定：**方案 C「双页书本」**。原型在分支 `prototype/reader-ui`（`prototype/reader-demo.html`），只作参考，正式代码重写。

## 1. 总体做法

一个在本机运行的网页。启动一条命令，浏览器打开 `http://localhost:8766` 就能读书。不用服务器，不联网，书和阅读进度都存在这台电脑的浏览器里。

```
你选的 .epub 文件
      │  第一次打开时存一份
      ▼
浏览器的大容量存储（IndexedDB）── 书、阅读位置、设置、上次读的书
      │
      ▼
epub.js（开源 EPUB 显示工具）── 解析、分页、双页显示、目录
      │
      ▼
我们自己写的界面 ── 方案 C 的书页、底部工具栏、目录和设置弹窗
```

## 2. 用到的工具

| 工具 | 干什么 | 为什么选它 |
|---|---|---|
| **epub.js**（版本 0.3.93） | 读取 EPUB、自动分页、双页显示、目录、换主题 | 自带「双页、窄屏自动变单页」，正好是方案 C；用的人多，资料多 |
| **JSZip** | epub.js 需要它来解压 EPUB（EPUB 本质上是个压缩包） | 安装 epub.js 时自动带上，不用单独装 |
| **Vite** | 开发时启动本地网页，发布时打包 | 配置最少，一条命令启动 |
| **Vitest** | 单元测试：检查存储、书的编号等小零件 | 和 Vite 配套，几乎不用配置 |
| **Playwright** | 自动操作浏览器，按产品文档的 5 条验收标准逐条测试 | 能用电脑上已经装好的 Chrome，不用另外下载浏览器 |

不用 React 之类的前端框架：只有一个页面、几个按钮，普通网页代码足够，少一层东西就少一层出错的地方。

**风险：** epub.js 0.3.93 发布于 2022 年 2 月（已核对 npm 的发布时间），之后没有正式新版，基本停止更新。

**已知安全提示：** `npm audit` 报告 epub.js 依赖的 xmldom 有漏洞。核对过源码：epub.js 只在没有浏览器的环境（Node / 老 IE）才用 xmldom，在 Chrome 里用的是浏览器自带的解析器，所以这些漏洞碰不到阅读器；书也都是自己的文件。不要照 npm 的提示「修复」：它会装 2018 年的 epubjs 0.4.2，反而更旧。如果碰到修不好的问题（比如某些书显示错乱），备选是 **foliate-js**（Foliate 阅读器在用的显示引擎，维护更活跃，但没有正式的安装包，资料也少）。第一步就用两本真实的书去试 epub.js（见第 8 节 M1），尽早发现问题。

## 3. 数据怎么存

全部存在浏览器的 IndexedDB 里，分 4 类：

| 存什么 | 内容 | 什么时候写 |
|---|---|---|
| `books` | 书的原始文件 + 书名、作者、语言 | 第一次打开这本书时 |
| `positions` | 每本书读到哪（见下文「位置坐标」）+ 百分比 | 每次翻页后（停顿 0.5 秒再写，避免连续翻页时写太多次） |
| `settings` | 字号、深色/浅色 | 每次修改后 |
| `meta.lastBookId` | 上次在读哪本书 | 打开或换书时 |

**书的编号：** 用文件内容算出一个「指纹」（SHA-256）作为编号。同一本书重复选择，会认出来是同一本，接着上次的位置读，不会存两份。

**位置坐标：** 不记「第几页」，而是记 EPUB 标准里的位置坐标（CFI），它指向「某章第几段第几个字」。好处是改字号、改窗口大小以后页数会变，但坐标不变，回来时仍然停在同一段文字上。原型里「改字号后页码跳动」的问题，正式版用这个方法解决。

## 4. 打开网页时的流程

```
打开网页
  ├─ 读 meta.lastBookId
  │    ├─ 有 → 从 books 取出那本书 → 用 positions 里的坐标打开 → 直接显示（不用任何操作）
  │    └─ 没有 → 显示空白首页「选择 EPUB 文件」
  └─ 读 settings → 应用字号和深浅色

选文件
  └─ 算指纹 → 新书就存进 books → 打开（新书从头，老书接着读）→ 更新 lastBookId
```

## 5. 方案 C 各部分怎么做

| 界面部分 | 做法 |
|---|---|
| 双页书本 | epub.js 的「双页」模式（`spread: "auto"`）。窗口宽度小于约 800px 时自动变成单页 |
| 翻页 | 底部 ◀ ▶ 按钮 + 键盘 ← →。注意：书的内容显示在一个独立的小窗口（iframe）里，键盘事件要在书页里也监听一次，不然点了书页以后按键没反应 |
| 进度条 | epub.js 先给全书算一遍「位置表」，进度条才能显示百分比、拖动跳转。大书算一次可能要几秒，算好后存进 IndexedDB，下次直接用 |
| 目录 | 读 EPUB 自带的目录，做成底部弹出的列表，当前章节高亮，点一下跳转 |
| 字号 / 深色 | epub.js 的「主题」功能，把样式注入书页；工具栏和背景同时换色 |
| 中文排版 | 根据书的语言信息（`zh` 开头）给书页加中文样式：宋体类字体、行距 1.85、首行缩进 2 字、两端对齐。英文书用另一套。书本身自带的样式优先级要压过去，否则不同的书效果不一样 |
| 换书 | 工具栏「换书」→ 打开电脑的文件选择框（只允许 `.epub`） |
| 读完 | 最后一页再往后翻，显示「读完了」 |

## 7. 测试

按项目规范，每次改动都要有对应测试，交付前全部通过。

**测试用的书：** 用脚本自己生成两本小 EPUB（一本中文、一本英文，多章节、带目录、有一张图片），内容是自己编写的文字，不涉及版权，也能保证每次测试结果一致。此外，Emily 用自己的 1～2 本真书人工检查一遍，因为真书的排版比测试书复杂得多。

| 产品验收标准 | 自动测试怎么检查 |
|---|---|
| 1. 打开 EPUB | 中、英文测试书各打开一次：书名、第一章文字、图片都显示出来，没有乱码 |
| 2. 翻页 | 从第一页连续按 → 到最后，出现「读完了」，中途没有报错 |
| 3. 章节目录 | 点 3 个不同章节，显示的章节标题都对 |
| 4. 记住读到哪里 | 读到第 3 章某页，关掉页面、重新打开，不做任何操作：同一段文字出现在屏幕上 |
| 5. 字号 / 深色 | 改字号、切深色后重新打开，设置还在，位置也没跑 |

另外再测两种情况：窄窗口下变成单页；同一本书选两次，只存了一份。

**跑测试：** `npm test`（单元测试）、`npm run test:e2e`（浏览器测试）。

### M1 的真书检查

用 Emily 正在读的书：`~/Downloads/AI-Agents-in-Depth-zh-CN.epub`（《深入理解 AI Agent》，中文，无加密，3.4 MB）。这是一本技术书，双页时每页只有半屏宽，最容易出问题：

| 检查项 | 书里有多少 | 要看什么 |
|---|---|---|
| 代码块 | 56 段 | 长代码行有没有被截掉；能否横向滚动或自动换行 |
| 表格 | 36 个 | 宽表格放不放得下 |
| 数学公式（MathML） | 96 处 | 能否正常显示 |
| 图片 | 114 张 | 缩到半页宽后是否还看得清 |
| 脚注 | 132 个 | 点了能不能看到注释、能不能回到原处 |
| 目录 | 13 章 / 88 节 | 两级目录是否都能显示和跳转 |

如果代码和表格在双页里明显读不下去，备选做法：加一个「单页 / 双页」切换按钮，每本书记住自己的选择（技术书用单页，小说用双页）。

**检查结果（2026-11-05，脚本 `npm run check:book -- <书> <输出文件夹>`，屏幕 1440×900，双页时每页 468px 宽）：**

| 检查项 | 结果 |
|---|---|
| 代码块 56 段 | ✅ 书自带的样式会自动换行，双页、单页都没有被截掉的 |
| 表格 36 个 | ✅ 都放得下，格子里的字自动换行 |
| 数学公式 96 处 | ✅ 全部正常显示（分数、下标、求和符号） |
| 图片 114 张 | ⚠️ 都能显示，但**图表缩到半页宽后，图里的小字看不清**；单页时清楚 |
| 脚注 132 个 | ⏳ 只数了数量，点击跳转和返回留到 M3 做目录时一起处理 |
| 目录 | ⚠️ 共 295 条（14 章，三级），临时下拉框能用但太长；M3 的目录弹窗要能折叠 |
| 页面报错 | ✅ 无 |

结论：epub.js 能用，不用换 foliate-js。双页的唯一明显问题是图表太小。

这本书只在本机人工检查用，不放进仓库、不提交（有版权）。

## 9. 怎么运行

```
npm install        # 第一次：安装工具（需要联网）
npm run dev        # 启动，然后在浏览器打开 http://localhost:8766
```

- 端口固定为 **8766**（避开了本机其他程序常用的端口）。端口被占用时直接报错，不会自动换成别的端口，否则浏览器会因为地址不同找不到之前存的书。
- 不能直接双击 `index.html` 打开：浏览器对直接打开的本地文件限制很多，epub.js 和存储都可能出问题，必须通过上面的本地网址打开。
- 以后可以做一个双击就能启动的小图标，第一版先不做。

## 10. 已知的限制和问题

| 问题 | 影响 | 处理 |
|---|---|---|
| 换浏览器或清空浏览器数据，存的书和进度都会丢 | 要重新选文件，从头读 | 第一版接受；以后可以加「导出 / 导入进度」 |
| 很大的书（几百 MB 的图册） | 存储和计算位置表会慢 | 第一版不管，遇到再说 |
| 带加密（DRM）的书 | 打不开 | 不支持，打开时提示「这本书有加密，无法打开」 |
| Claude Code 的沙箱可能不允许启动本地网页 | 开发时我这边启动不了 | 在设置里打开 `sandbox.network.allowLocalBinding`，或由 Emily 用 `!` 自己启动 |
